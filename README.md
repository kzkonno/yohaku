# Yohaku

睡眠、食事、通勤、仕事、身支度などから、まとまって使える自由時間を見つけるAndroidアプリです。KotlinとJetpack Composeで実装しています。

## 使い方

1. 「平日」「休日」を選び、サンプルの予定を自分の生活に合わせて編集します。
2. 「予定を追加」から名前、分類、開始・終了時刻を登録します。終了時刻が開始より前なら翌日までの予定です。
3. 「自由時間の条件」で必要な連続時間（15 / 30 / 60 / 90分）と予定前後の余裕（0 / 5 / 10 / 15分）を選びます。
4. 円グラフで1日の比率、自由時間カードで具体的な時刻、タイムラインで生活の配分を確認します。

予定と条件は端末内に自動保存します。アカウントやネットワーク権限は不要です。予定の削除は編集画面から行います。

## 計算の定義

- 1日は現地の時計上の0:00〜24:00、1分単位の繰り返しテンプレートです。
- 重なる予定は集合として統合し、生活時間を二重に数えません。
- 各予定の前後に余裕時間を確保します。余裕は日付境界もまたぎます。
- 残った空き枠が設定した連続時間以上なら、その枠全体を「本当に使える自由時間」に加算します。
- 「余裕・短い空き」は未使用時間のうち自由時間に含めなかった分です。生活・仕事＋余裕・短い空き＋使える自由時間＝1440分です。
- 自由時間は0時で分割します。日付別の例外、祝日自動判定、夏時間による23/25時間の日、実際の疲労や集中力の推定には対応していません。
- 初期平日は生活・仕事21時間15分、空き2時間45分。前後5分・連続30分の条件では、19:50〜20:25と21:05〜22:55の計2時間25分が使えます。

## 開発・ビルド

Android 8.0（API 26）以上に対応します。JDK 17とAndroid SDK Platform 36を用意してください。

Android Studioでこのディレクトリを開くか、SDKパスを`local.properties`の`sdk.dir`に指定して実行します（このファイルはGit管理対象外）。

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

macOSでJDKが複数ある場合は `export JAVA_HOME=$(/usr/libexec/java_home -v 17)` を先に実行します。

生成するAPKは開発用のdebug署名です。配布用の署名鍵は含めていません。

## 構成

- `Schedule.kt`: 日付跨ぎ、重複、余裕、連続時間の計算。Android UIから独立した純粋Kotlin。
- `MainActivity.kt`: Compose画面、ネイティブ時刻ピッカー、端末内保存。
- `ScheduleTest.kt`: 日付境界、重複、全日占有、しきい値などのJUnitテスト。

依存関係はAGP 8.10.1、Gradle 8.11.1、Kotlin 2.1.20、Compose BOM 2025.04.01に固定しています。

## Health Connectと睡眠の補正（v1.1.0）

「日付別の記録」→「Health Connectに接続」から、睡眠の読み取りを許可してください。計測元アプリからHealth Connectへの睡眠の書き込みも必要です。

- 接続後はアプリを開く・戻るたびに直近29日間を自動取得します。「再同期」でも更新できます。常駐やバックグラウンド取得はしません。
- 日付を選び、睡眠記録をタップすると開始・終了の日付と時刻を修正できます。
- 二度寝は「二度寝・別端末の睡眠を追加」で別の枠として追加します。Apple Watchの記録も手入力し、計測元を選べます。Appleヘルスケアへの直接接続やファイル取り込みは実装していません。
- 自動取得の元時刻とアプリ内の修正を別々に保持し、同じHealth ConnectレコードIDの再同期では修正を上書きしません。「取得した時刻に戻す」で修正を取り消せます。
- 取得記録の「非表示」は再同期でも維持し、後で戻せます。手入力記録は削除できます。
- 取得元から消えた未修正レコードは、取得範囲内なら同期時に除去します。修正済みレコードは元が消えても維持します。別IDで再作成された記録は別件として表示し、重なる時間の集計は統合します。
- 睡眠枠はセッションの開始〜終了（途中の覚醒を含む）です。自由時間の見積もりでは、途中の覚醒を自動的に自由時間として数えません。
- その日と交差する記録を現地時間の0〜24時に切り出します。日跨ぎの記録自体は分割せず保存します。集計は時計上の固定1440分モデルで、夏時間切替日の実経過時間とは異なる場合があります。
- 睡眠記録と重なる基本の睡眠予定の枠を記録で置換し、それ以外の予定は残します。未入力を「睡眠0分」とは扱いません。仕事・食事等は基本の予定を引き続き利用するため、自由時間は実測値ではなく見積もりです。
- 読み取り失敗や権限取消時も保存済みデータは保持します。同期中に編集しても、同期結果は最新のローカル修正とマージします。
- 停止ボタンは自動読取を停止します。権限自体はHealth Connect設定で取り消せます。全ローカルデータの消去はAndroidのアプリストレージ消去から行えます（基本の予定も消えます）。

Health Connectには睡眠の読み取り権限だけを要求します。書き戻し、ネットワーク通信、睡眠ステージ・心拍数の保存はありません。Health Connect対応はAndroid 9以上かつ利用可能な端末に限り、利用不可の場合は手入力を利用できます。

公式仕様: [導入と権限](https://developer.android.com/health-and-fitness/health-connect/get-started)、[睡眠セッション](https://developer.android.com/health-and-fitness/health-connect/features/sleep-sessions)、[読み取りとページング](https://developer.android.com/health-and-fitness/health-connect/read-data)。
